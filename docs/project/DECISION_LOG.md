# Decision log

| Decision                               | Rationale and evidence                                                                                                                                                                                                           |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Modular monolith on Cloudflare         | One application deploy and clear boundaries without distributed transactions; original `docs/architecture.md`, current `app/`, `modules/` and `worker/index.ts`.                                                                 |
| Google identity, application admission | Google verifies identity; existing provisioned account and stable subject determine access. Roles are application records, not domain inference. Alternate Cloudflare Access is retained in source; not deployed auth mode here. |
| D1 for relational state; R2 for bytes  | FK-constrained metadata and audited business state are separate from private file bytes; retain scoped app download route and independent recovery steps.                                                                        |
| Resend and Google Chat                 | Independent notification transports; D1 stores claim/history, uncertain sends cannot trigger blind fallback. Normal publication and isolated previews must never share a queue.                                                  |
| Invitation architecture                | Authorized, pre-provisioned employee invite sends an ordinary Google sign-in link, not a bearer token or automatic provisioning. Admin preview uses fixed recipient and separate audit intent.                                   |
| Mobile and extension                   | Retain versioned API and source; delivery intentionally deferred per owner. Earlier work is historical and does not certify current release.                                                                                     |
| Domain architecture                    | Keep Route 53 authoritative; use CNAME to Pages gateway and explicit service binding to Worker. Keep the existing configured email origin until an approved, tested OAuth/cookie/URL cutover.                                    |
